# 找片自动转存 · 蓝图（定版 v1）

项目名：**PanHarbor**（仓库 panharbor）。命名不绑夸克：Pan 指网盘（不限哪家），Harbor 指把片子收进港湾。代码按驱动架构写：搜索源（pansou）与网盘驱动（v1 只有夸克）各是独立模块，后续加百度/阿里/115 等网盘只新增一个驱动文件，不动主流程。

日期：2026-11-18
状态：核心链路已实测通过（夸克转存五步），v1 已实现，本文为设计记录

## 1. 目标与边界

做一个单独 Web 应用（单 Docker 容器，部署在任意支持 Docker 的机器上）：输入片名 → 自动搜夸克资源 → 挑版本 → 生成清洗后的转存计划 → 确认 → 转存到夸克指定目录（电影/电视剧）并规范命名 → 验收回报。

不做：STRM、播放、下载落盘、追更订阅（一期不做，二期可选）、多用户、公网开放给他人。

## 2. 总体架构

一个 Docker 容器，前后端一体，常驻运行，全部逻辑在部署机本地：

```
浏览器 ──> [Web 应用容器]
              ├─ 前端页面（搜索 / 计划预览 / 任务历史 / 设置 / 状态）
              ├─ pansou 客户端 ──出站──> pansou 服务地址（直连后端，或经反向代理中转；搜索，只要夸克）
              ├─ 计划生成器（清单解析 + 清洗规则，纯本地逻辑）
              └─ 夸克客户端 ──出站──> drive-h.quark.cn（用本地配置的 Cookie）
                     列目录 / 换 stoken / 列分享 / 保存 / 轮询 / 改名 / 移动 / 建夹
```

要点：

- 无外部调度参与日常运行：容器是常驻服务，点击即执行。
- pansou 地址填部署机能实际访问到的那个：可直连后端，也可经反向代理/中转访问，应用不关心中间链路，只认最终地址。
- 凭证不出部署机：夸克 Cookie 只存容器数据卷的配置文件（权限 600）。
- 技术栈（默认，可改）：Python + FastAPI + SQLite + 原生前端页面。理由：已实测通过的验证脚本就是 Python，夸克客户端逻辑可直接复用；镜像小、内存占用低。备选 Java/Spring Boot（熟悉 Java 的团队更易维护，但镜像和内存更大）。

## 3. 页面（共 5 个）

1. **搜索页**：片名输入框 + 备注（可选，如“只要 4K”）；结果以候选卡片列出：标题、体积、文件数/集数、清晰度标签（从文件名解析）、链接有效性（已验/已失效）。每张卡片一个“选它”按钮。
2. **计划预览页**（核心页）：选中候选后生成。分两栏：将存（清洗后文件名、集号、体积）/ 将跳过（逐个带原因）。片名可改、分类（电影/电视剧）可选、单文件可勾选增减。点“确认转存”才执行。
3. **任务页**：进行中任务的实时阶段（保存中/改名中/验收中）和进度；历史任务列表及结果（存入路径、文件数、缺集报告）。
4. **设置页**：夸克 Cookie 填写与验证（验活结果、账号容量、上次验活时间）；电影目录、电视剧目录选择（从夸克目录树里点选，存 fid）；pansou 地址；质量偏好（默认 2160p > 1080p > 720p，同档取体积大）；访问密码修改。
5. **状态页**：pansou 可达性、Cookie 有效性、夸克剩余容量、最近任务成败统计。一眼看出哪一环坏了。

## 4. 核心流程与状态机

任务状态：`搜索中 → 待选版 → 计划待确认 → 保存中 → 改名中 → 验收中 → 已完成 / 部分完成（缺集）/ 失败（带原因）`

1. 搜索：后端调 pansou `/api/search`（kw=片名，cloud_types=["quark"]，res=merge），合并去重。
2. 验链：对候选逐条轻量验活（用夸克客户端换 stoken + 列分享首页，能出文件才算活），失效的直接标灰。只验前 N 条（默认 10），防触发夸克频控。
3. 选版：用户点选一张卡片。
4. 生成计划：递归列出该分享全部文件 → 跑清洗规则（第 5 节）→ 出计划预览。
5. 执行保存：先在目标分类目录下建干净文件夹（名=片名，年份可选），再按计划把选中文件 fid 分组提交保存（按源父目录分组），轮询任务至完成。
6. 改名整理：逐个改名为规范名；字幕跟随对应集同名；季目录重建为 Season 结构。
7. 验收：列目标文件夹，与计划比对（数量、集号连续性），生成结果（齐全/缺哪几集），写入任务历史。

失败兜底：保存失败（死链、分享取消）时在任务页标明原因，并提供“一键试下一个候选”（回到第 4 步，计划重新生成）。

## 5. 清洗规则（计划生成器）

解析：从文件名提取集号（S01E05 / 第05集 / EP05 / E05 / 纯数字序号）、季号、清晰度标签、年份。

保留：

- 视频文件（mkv/mp4/avi/ts/m2ts/mov/rmvb/webm/flv），按集号分组
- 字幕（srt/ass/ssa），按集号与视频配对
- 分卷电影（CD1/CD2、Part1/2）全留并规范命名

跳过（高置信才跳，逐个写明原因）：

- 非媒体杂文件：txt/html/url/exe/bat、二维码与推广图片、说明文档
- 体积明显过小（默认 < 30MB）的视频：多为预告/样片/广告片段
- 同集重复版本：按质量偏好只留最佳一份（其余列入跳过栏，用户可在预览页勾回）
- 文件名含“预告/花絮/彩蛋/访谈”等标记的视频（列入跳过栏，可勾回）

不确定不删：解析不出集号、无见过类型的文件，一律保留并在预览页标黄。

特殊情况：

- 整包压缩文件（zip/rar/7z）：无法挑内含物，整包保留并标明
- 规范命名：电视剧 `片名.S01E05.mkv`；电影 `片名 (年份).mkv`；分享方原文件夹名一律不用

## 6. 接口清单（已验状态）

- `POST /api/search`：已确认接口形态；开发前抓一次真实响应样本定字段

夸克（drive-h.quark.cn，带 Cookie，pr=ucpro&fr=pc）：

- 列自有目录 `/file/sort` ✅ 已实测
- 换 stoken `/share/sharepage/token` ✅ 已实测
- 列分享 `/share/sharepage/detail` ✅ 已实测（顶层；递归翻子目录开发时补验）
- 提交保存 `/share/sharepage/save` ✅ 已实测（顶层文件）

- 容量/账号信息：设置页验活用，开发时定

## 7. 配置项（存容器数据卷，设置页可改）

- QUARK_COOKIE（600 权限，不进镜像、不进日志）
- MOVIE_FID / TV_FID（电影、电视剧目标目录）
- PANSOU_BASE（pansou 服务地址，填部署机可达的地址）
- PANSOU_USERNAME / PANSOU_PASSWORD（pansou 认证账号，设置页填写，token 由应用自动换取和刷新）
- QUALITY_ORDER（质量偏好顺序）、MIN_VIDEO_MB（小文件阈值，默认 30）
- APP_PASSWORD（页面访问密码）
- CHECK_LIMIT（验链条数上限，默认 10）

## 8. 部署与访问安全

- docker compose 单容器：端口默认 18090（可改），数据卷 `./data:/app/data`，restart: unless-stopped，内存限额 256MB。
- 访问方式（默认）：置于带 HTTPS 的反向代理之后 + 应用自身密码登录，或仅在可信内网中使用；不在公网裸奔端口。此页握有夸克写权限，按敏感服务对待。
- 日志：只记任务与接口成败，不记 Cookie、不记完整分享链接以外的敏感项。

## 9. 数据

SQLite 单文件（数据卷内）：

- tasks：片名、备注、候选快照、计划快照、状态、结果、时间
- settings：键值表（Cookie 加密与否见拍板项，默认明文 + 文件 600）

## 11. 分期

一期（MVP）：五页全量 + 第 4 节流程 + 第 5 节规则 + 失败换候选。
二期（可选）：追更订阅（订一部剧，定时重搜 pansou、只转新集、自动清洗改名）；转存完成消息推送；TMDB 补海报/年份美化卡片。

## 12. 风险与兜底

- Cookie 过期：状态页常驻验活，过期时任务页明确提示去设置页更新（从浏览器重新取一份）
- 夸克改接口：夸克客户端单模块隔离，改动面小；每次保存失败保留原始返回便于定位
- 重复转存：保存前先查目标文件夹已有集号，已有集自动跳过（顺带支持二期追更增量）
- 容量不足：计划页显示预计体积 vs 剩余容量，不足时先警告再执行
- 误删防线：一期不在用户网盘内做删除动作；清洗靠“不提交”实现，跳过的文件根本不进来

## 14. 验收标准

- 搜一部电影：从输入到计划页 ≤ 15 秒，候选均标有效性
- 转存一季 12 集（分享内含杂文件与双版本）：落盘只有 12 个规范命名视频 + 对应字幕，缺集报告准确
- 故意用一条死链：任务失败原因明确，一键换候选可继续
- Cookie 人为改错：状态页与任务页都能明确报“登录过期”，不静默失败

## 15. 代码仓库与打包运行

- 代码唯一存放地：一个 GitHub 私有仓库，开发、提交、版本标签都在仓库里。部署机上是部署副本；数据（Cookie、SQLite、日志）只在部署机数据卷里，永不进仓库。
- 仓库结构（定版）：

```
/
├─ README.md            # 快速开始、架构一页图、配置表、常见问题
├─ docker-compose.yml   # 一键启动
├─ Dockerfile
├─ .env.example         # 全部配置项带注释，只有占位符、无真实值
├─ .gitignore           # .env、cookie、data/ 一律排除
├─ app/                 # 后端（FastAPI：pansou 客户端 / 夸克客户端 / 计划生成器 / 任务执行）
├─ app/static/          # 前端页面
├─ tools/               # 验证脚本（quark_save_test.py 等，开发前验证项用）
└─ docs/                # 本蓝图、接口笔记、验证记录
```

- 打包运行（写进 README，按此验收）：
  1. 前置：部署机已装 Docker；能访问 pansou 服务地址
  2. 把仓库放到部署机一个目录（git clone；若部署机拉取不畅，改用源码包上传解压，README 写明两条路）
  3. `cp .env.example .env`，只填访问密码一项（Cookie 和目录 fid 首次登录后在设置页里填/选，不写文件）
  4. `docker compose up -d --build`，打开 `http://服务器地址:18090` 登录
  5. 设置页：填 Cookie 点验证 → 选电影/电视剧目录 → 状态页全绿即完成
- 更新：`git pull`（或换新源码包）后 `docker compose up -d --build`，数据卷不动、配置不丢；回滚：切回上一个版本标签同样命令重建。
- 排障：README 给 `docker compose logs -f` 的看法和五种常见报错（Cookie 过期、pansou 不可达、端口占用、容量不足、死链）各自的处理。
